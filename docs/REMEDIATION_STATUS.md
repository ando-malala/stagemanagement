## Politique d'accès

ADMIN : périmètre global. RESPONSABLE_STAGE : départements attribués, selon le département de la structure du stage. ENCADREUR : participations réellement affectées au compte encadreur. STAGIAIRE : dossier explicitement associé au compte. Les rôles cumulés donnent l'union des droits.

Le département nullable du dossier stagiaire permet les admissions avant affectation. Un dossier historique non rattaché reste consultable à travers une participation autorisée ; sa modification reste réservée à ADMIN avant qualification du département. Aucune association n'est déduite d'un nom ou d'un courriel. Le compte lié doit être actif, avoir le rôle STAGIAIRE actif et ne pas appartenir à un autre dossier.

Une alerte ou un fichier associé à plusieurs dossiers exige l'autorisation sur toutes ses cibles. Les alertes globales de surcharge sont masquées si elles incluent des participations hors du périmètre ; le tableau de charge compte uniquement les participations accessibles.

## Vérifications réellement exécutées

- **Backend : 30 tests réussis, 0 échec, 0 ignoré** : 23 unitaires (clôture, règles, accès, contenu, export, suivi) et 7 Spring/HTTP/PostgreSQL (5 scénarios métier complets, 2 tests de sécurité applicative).
- Commande : `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/test-integration.ps1`. Dernière base : `mef_integration_6e587ae50aef46f1afb003e3815dbe51`. Schéma importé seulement après création de cette base vide, puis V001/V002. Précontrôle SQL exécuté en lecture seule avec succès. La base de test est conservée ; ses fichiers temporaires sont nettoyés. Elle n'est donc pas un jeu de sauvegarde documentaire réutilisable.
- Le test des détecteurs utilise les vrais services/repos PostgreSQL. Le bean de planification est remplacé pour empêcher un déclenchement intempestif ; une orchestration explicite appelle les sept détecteurs réels. Cela ne prouve pas le déclenchement du cron dans une installation future.
- **Frontend : 106 tests Node réussis**, incluant contrats HTTP, erreurs réseau, permissions, rendu SSR React et serveur HTTP local de test. Les fixtures frontend ne remplacent pas les réponses serveur de l'application ; les nouveaux endpoints sont aussi testés sur Spring/PostgreSQL.
- ESLint réussi ; Vite build réussi, 120 modules. Commandes : `node node_modules/eslint/bin/eslint.js .` et `node node_modules/vite/bin/vite.js build` depuis `frontend`.
- `mvn.cmd -o -f backend/pom.xml -DskipTests package` : réussi, JAR Spring Boot produit après la suite d'intégration. Ce packaging n'a pas réexécuté les tests.
- Inventaire régénéré : 53 contrôleurs, 298 opérations, 125 admises par Spring Security. Les CRUD bruts non autorisés restent fermés.
- Aucun E2E pilotant un navigateur, contrôle mobile/clavier, dialogue d'impression, test de charge ou restauration de sauvegarde de production exécuté.

Les échecs de mise au point (ancien faux PDF de test, verrou d'écriture dans un mapper de lecture, nom de table erroné dans un nouveau jeu de test) ont été corrigés puis la suite complète relancée. Ils ne sont pas comptés comme validations réussies.
