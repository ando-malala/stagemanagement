APJ : Application Personnalisée JRews, framework en java créé par les équipes de JRews (ancien nom de la BICI). Cc : Abréviation de "Copie conforme" ou "Carbon copy", désignant les destinataires en copie d'un courrier électronique. CDN : Content Delivery Network, réseau de distribution de contenu permettant de stocker et diffuser des fichiers (images, vidéos) de manière rapide et fiable via des serveurs répartis géographiquement. CRON : Utilitaire de planification de tâches sous systèmes Unix/Linux permettant d'exécuter automatiquement des commandes à des intervalles définis. EJB : Enterprise JavaBeans, composants Java EE permettant de développer la logique métier côté serveur avec des fonctionnalités comme la gestion des transactions et la planification de tâches. GED : Gestion Électronique des Documents, système informatisé permettant de numériser, classer, archiver et consulter des documents de manière centralisée. Hibernate : Framework ORM (Object-Relational Mapping) pour Java facilitant la conversion et la manipulation des données entre une base de données relationnelle et des objets Java. HTML : HyperText Markup Language, langage de balisage utilisé pour créer et structurer le contenu des pages web. HTTP : HyperText Transfer Protocol, protocole de communication utilisé pour transférer des données entre un client et un serveur web. IA : Intelligence Artificielle, ensemble de technologies permettant aux machines de simuler l'intelligence humaine pour analyser, interpréter et prendre des décisions automatiquement. Java EE : Java Enterprise Edition, plateforme de développement d'applications d'entreprise offrant des API et services pour créer des applications distribuées robustes. JSP : JavaServer Pages, technologie permettant de créer des pages web dynamiques en intégrant du code Java dans du HTML côté serveur. PageRecherche : Classe du framework APJ utilisée pour la gestion et l'affichage de listes de données dans les applications Async. PDF : Portable Document Format, format de fichier permettant de présenter des documents de manière identique quel que soit le logiciel ou système utilisé. Reporting : Processus de collecte, analyse et présentation de données sous forme de rapports structurés pour faciliter la prise de décision en entreprise. 6 === PAGE PDF 7 === RESTful : Architecture de services web basée sur le protocole HTTP utilisant les méthodes GET, POST, PUT, DELETE pour créer des API simples et interopérables. SGBDR : Système de Gestion de Base de Données Relationnelles, logiciel permettant de créer, gérer et interroger des bases de données organisées sous forme de tables reliées. XML : eXtensible Markup Language, langage de balisage permettant de structurer et échanger des données de manière standardisée entre différentes applications. 7 === PAGE PDF 8 === Avant-propos Le présent mémoire présente les résultats du travail effectué lors de mon stage de fin d’études de Licence en Informatique à l’IT University. Dans le cadre de mon stage, j’ai pu constater que la disponibilité d’informations fiables et actualisées constitue un enjeu majeur pour le pilotage d’une entreprise. Qu’il s’agisse d’un Compte Rendu Journalier (CRJ) , d’un Compte Rendu Hebdomadaire (CRH) ou encore d’un Compte Rendu Mensuel (CRM) , chacun joue un rôle déterminant dans le suivi des activités et l’aide à la décision. En effet, plusieurs études montrent que les organisations privilégient le suivi rapproché : 76 % d’entre elles mettent à jour leurs tableaux de bord quotidiennement afin de disposer d’une vision claire et précise des performances (zipdo.co). Toutefois, le reporting hebdomadaire reste essentiel pour analyser les tendances sur une période plus longue et ajuster les priorités, tandis que le reporting mensuel permet de dresser un bilan consolidé et stratégique. Ces pratiques ont un impact direct sur la performance : 78 % des responsables estiment que ces rapports sont indispensables pour prendre des décisions éclairées (wifitalents.com), et 66 % des utilisateurs déclarent une amélioration de leur productivité grâce à ces outils (wifitalents.com). Par ailleurs, l’automatisation du reporting offre un gain de temps considérable , puisque 47 % des analystes économisent au moins 5 heures par semaine grâce à ces rapports structurés (wifitalents.com). Enfin, cette démarche s’inscrit dans une tendance plus globale, car 98,6 % des dirigeants cherchent à instaurer une culture orientée données dans leur organisation ( fanruan.com ). Ainsi, qu’il soit quotidien, hebdomadaire ou mensuel, le compte rendu ne constitue pas seulement un outil administratif : il représente un levier stratégique de pilotage, de transparence et d’amélioration continue , adapté aux différents niveaux de suivi et de décision d’une entreprise moderne. Chez BICI, souhaitant intégrer la génération et l'automatisation de ces comptes rendus dans les applications Async, je me devais de le faire sans pour autant détériorer les performances de ces applications. Ce système d'information apportera donc à BICI les résultats suivants : ● Générer un rapport généralisé pour l’intégrer dans Async. ● Utiliser une couche d’intelligence artificielle pour enrichir les rapports. ● Automatiser l’envoi des rapports (journalier, hebdomadaire, mensuel). ● Développer une application Java Swing (générateur de code) pour l’intégration de ces modules. 11 === PAGE PDF 12 === Cette œuvre est organisée en trois sections principales. Il sert de base pour le développement et la réalisation de projets. Ce framework contient tous les modules utiles et nécessaires pour faciliter le processus de développement. Avantages du framework APJ pour le projet : ● Basé sur Java : Le framework est basé sur Java, un langage de programmation robuste et polyvalent qui est particulièrement adapté aux projets basés sur des statistiques, de grands traitements de données et des prédictions. Java est un langage orienté objet, ce qui offre des fonctionnalités comme l'héritage, la surcharge de méthode et le polymorphisme . La réutilisation de code ainsi que la division du code en plusieurs modules assurent la maintenance facile du code. La réduction des risques de régression du code est aussi assurée durant le développement car la modification du code lors du changement de comportement d’une fonctionnalité n’est plus une obligation grâce à la surcharge de méthode et au polymorphisme. De plus, Java assure la fiabilité des données dans les résultats des calculs car il gère bien les types de données. ● Modules intégrés : Le framework contient tous les modules utiles et nécessaires pour le développement et la réalisation de projets, ce qui accélère le processus de développement. ● Prise en main simple et rapide : Le framework est facile à comprendre et à utiliser, ce qui permet aux développeurs de se concentrer sur la réalisation du projet plutôt que sur la configuration de l'environnement de développement. 15 === PAGE PDF 16 === ● Gain de temps : Grâce au framework, l'écriture de code répétitif est minimisée, ce qui accélère le processus de développement. ● Gestion de l'ORM pour Oracle et Java : Le framework facilite la conversion des données entre le système de base de données Oracle et le langage de programmation Java, ce qui simplifie grandement le processus de développement. Par rapport aux autres ORM comme Hibernate, la méthode d’APJ présente des avantages car une mauvaise manipulation d’Hibernate peut entraîner une surcharge de requêtes affectant la performance de l’application. Hibernate peut aussi engendrer une dépendance entre la structure du code et la structure de la base de données à cause des annotations spécifiques à Hibernate pour la gestion des relations entre les classes relationnelles. ● Gestion de l'ORM pour PostgreSQL Java : Le framework prend également en charge l’interaction entre PostgreSQL et Java, ce qui rend plus simple la manipulation et la conversion des données entre la base et l’application. Grâce à cette approche, les développeurs n’ont pas à écrire manuellement toutes les requêtes ou à gérer directement les résultats en objets Java, ce qui fait gagner du temps et réduit les risques d’erreurs. Contrairement à Hibernate, qui peut parfois générer une surcharge inutile ou compliquer la maintenance à cause des nombreuses annotations, la méthode proposée par APJ reste plus légère et plus directe. Elle permet aussi d’avoir un meilleur contrôle sur les requêtes exécutées, ce qui évite les problèmes de performance qui peuvent survenir avec un ORM trop automatisé. Alternatives Une alternative possible est Spring Boot . Bien que Spring Boot soit aussi développé en Java et bénéficie de quelques avantages cités ci-dessus, quelques-uns de ces atouts sont particulièrement intéressants pour améliorer et assurer un développement plus sûr du projet, tels que: ● L'intégration du service RESTful : Un service REST rend le projet plus facile à utiliser et à connecter avec d’autres applications, même si elles sont développées avec des langages différents. Spring Boot facilite énormément la création de ce type de service. Contrairement aux servlets classiques où il faut souvent gérer plusieurs contrôleurs et écrire beaucoup de code pour supporter différentes méthodes HTTP, Spring Boot permet de tout centraliser dans une seule classe ou un seul contrôleur. Cela réduit la répétition de code et rend l’architecture plus claire. De plus, comme 16 === PAGE PDF 17 === Spring Boot suit naturellement les conventions REST, le projet devient plus cohérent, plus facile à comprendre et plus simple à maintenir par d’autres développeurs qui connaissent déjà ce principe. ● Support de la communauté et documentation plus vaste : Spring Boot est en avance concernant la documentation et dispose d'une communauté plus large. En effet, Spring est utilisé par beaucoup d'entreprises et beaucoup de développeurs, donc la gestion d’erreurs et la recherche d'informations sur le sujet sont plus faciles et plus accessibles. 17 === PAGE PDF 18 === APJ Spring Boot Modules intégrés Oui Non ORM Manipulation n’affectant pas la performance Dépendance à la structure de la base Peut affecter la performance avec une mauvaise manipulation Restful Non Oui Documentation Documents internes Présents sur plusieurs sites et communautés. En effet, pour SmartAsyncReport , il est nécessaire d’enregistrer plusieurs données pour assurer le bon fonctionnement du module, notamment les adresses emails des destinataires des rapports, les configurations de base pour l’envoi ainsi que la configuration des contenus afin de garantir la qualité des rapports générés. 1.3.3.1 Oracle 11g R2 Express Edition (XE) Oracle est un système de gestion de bases de données relationnelles (SGBDR). En effet, pour les projets Async, on enregistre au minimum deux lignes de données (historisation des connexions et déconnexions) pour chaque utilisateur et par jour. Cela signifie que, dans une entreprise de 100 personnes, on obtient 200 lignes de données en une journée, 6 000 lignes en un mois et 72 000 en une année. Les systèmes d’exploitation possèdent chacun un planificateur de tâches, comme “Task Scheduler” pour Windows ou encore CRON pour Linux. Mais cette idée a été abandonnée car elle est efficace mais elle va dépendre du système d’exploitation du serveur client, donc un manque de flexibilité. ● Option 2: stocker l’heure d’envoi dans une table de configuration. J’ai aussi pensé que stocker l’heure dans une table serait une bonne idée. Mais cela va nécessiter une vérification toutes les minutes pour vérifier si l’heure actuelle correspond à l’heure d’envoi, ce qui peut entraîner une perte de performance lors de l’utilisation de l’application. ● Option 3: EJB Timer. Dans WildFly, l’ EJB Timer est un mécanisme qui permet d’automatiser l’exécution de tâches planifiées directement au sein de l’application. Grâce à l’annotation @Schedule , il est possible de définir des intervalles ou des horaires précis (par exemple tous les jours à 16h15) pour déclencher automatiquement une méthode. Cette fonctionnalité évite de dépendre d’outils externes comme le planificateur Windows ou CRON sous Linux, car la planification est directement gérée par le serveur d’applications. Figure 28 : Ged intégrée 2.2.2 SmartAsyncReport Description et importance SmartAsyncReport est une application Java Swing conçue pour faciliter l’intégration de tous les modules et fonctionnalités décrits précédemment. Elle agit comme un véritable générateur de code , capable de produire et d’intégrer automatiquement les classes, les pages et les servlets nécessaires dans une application Async choisie. En plus de la génération du code, l’application prend en charge l’importation de tous les éléments indispensables à la base de données : tables, vues, séquences, fonctions et données de base . Cette automatisation assure le bon fonctionnement des modules intégrés sans nécessiter de manipulation manuelle complexe. À l’issue de chaque génération, SmartAsyncReport conserve également un historique des projets sur lesquels il a déjà travaillé, permettant ainsi un suivi clair et une meilleure traçabilité des intégrations effectuées. L’utilisation de SmartAsyncReport revêt une importance stratégique pour BICI. En automatisant les tâches répétitives et fastidieuses liées à l’intégration et à la configuration, il permet de réduire considérablement le temps de développement (plus de 50% du temps est 43 === PAGE PDF 44 === économisé) voire de supprimer complètement le besoin de développement du module et de minimiser les risques d’erreurs humaines . De plus, en imposant une structure uniforme pour toutes les applications Async, il garantit une meilleure cohérence du code , ce qui facilite la maintenance et l’évolution future des projets. Enfin, il offre aux développeurs un outil puissant qui libère du temps pour se concentrer sur des tâches à plus forte valeur ajoutée, comme l’optimisation des fonctionnalités ou l’innovation. Scénario Un développeur chez BICI voudrait intégrer le module dans une application Async. Après cela, plusieurs étapes devront êtres suivi pour l'intégration: ● Étape 1: Configuration sur le projet Async, Dans cette partie, le développeur devra obligatoirement ajouter ○ le nom du projet, ○ l’heure d’envoi: l’heure d’envoi sera directement définie au moment de la génération de code pour la configuration de l’ EJB Timer, ○ le chemin d'accès vers le projet (avec le chemin de l’EJB et du WAR), ○ le nom du jar: l’application en aura besoin pour la Synchronisation Classe/JSON, ○ le fichier de déploiement ● Étape 2: Configuration de la base de données. C’est la partie la plus importante. Après la génération, l’application va conserver dans un fichier Historique.txt pour garder une traçabilité de l’historique de génération. ● Étape 5: Terminée. Cet étape est comme l’ analyse et statistique intégré dans l’application Swing, elle montre l’historique de génération suivi de ce qui s’est passé 44 === PAGE PDF 45 === lors de la génération (Succès ou Échec). Les images stockées localement ne pouvaient pas être directement envoyées via les services de messagerie, rendant les graphiques invisibles pour les destinataires. La solution adoptée a consisté à télécharger les images sur un CDN (imgBB) pour obtenir une URL publique accessible, puis à intégrer cette URL dans le HTML de l'e-mail, permettant ainsi aux destinataires de visualiser correctement les graphiques. Formatage des données numériques Le second problème identifié portait sur le formatage des données numériques dans les emails. Certains clients de messagerie n'interprétaient pas correctement le formatage utilisé, créant un affichage affichage étrange et incohérent des nombres, particulièrement au niveau des séparateurs décimaux et des milliers. Pour résoudre cette incompatibilité, j’ai décidé d’envoyer la version PDF en pièces jointes. 49 === PAGE PDF 50 === 3 Évaluation du projet et connaissances acquises 3.1 Bilan pour l'entreprise Grâce à ce projet, l’entreprise obtient un générateur de code performant qui minimise le temps nécessaire au développement du module et simplifie son intégration dans les applications Async.
